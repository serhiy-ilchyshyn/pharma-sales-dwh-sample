# Довідник даних — джерело, silver, gold

Опис для бізнес-користувачів: що лежить у кожному обʼєкті, як читати ключі та прапорці якості.
Опублікована версія цієї сторінки — див. посилання в README.

---

## 1. Джерело: Pharma ERP (Azure SQL, схема `erp`)

Облікова система дистриб'ютора. Дані вносять оператори й польова команда, тому тут є всі
природні дефекти: дублі, посилання «в нікуди», пропуски.

### Довідники

| Таблиця | Що містить | На що звернути увагу |
|---|---|---|
| `PRODUCTS` | Каталог препаратів: бренд, МНН, АТС-код, форма, дозування, виробник, базова ціна, RX/OTC | Один препарат може мати кілька рядків — історія зміни ціни/статусу |
| `CUSTOMERS` | Клієнти: аптеки, лікарняні аптеки, дистриб'ютори; ЄДРПОУ, мережа, регіон, місто | Та сама аптека трапляється двічі під різними кодами з тим самим ЄДРПОУ |
| `DOCTORS` | Лікарі: ПІБ, спеціальність, ЛПУ, регіон, сегмент A/B/C, ознака цільового | Той самий лікар буває заведений кілька разів |
| `EMPLOYEES` | Медпредставники та керівники, територія, лінія RX/OTC, дата найму | Керівник указаний кодом співробітника (ієрархія) |
| `WAREHOUSES` | Склади: власні, консигнаційні, транзитні | У консигнаційних власник — клієнт із `CUSTOMERS` |

### Операції

| Таблиця | Що містить | Зернистість |
|---|---|---|
| `SALES_ORDERS` | Продажі клієнтам (sell-out): кількість, ціна, знижка, сума, валюта, статус | Рядок замовлення |
| `INVENTORY_MOVEMENTS` | Рухи запасів: прихід, видача, переміщення, списання | Один рух |
| `DOCTOR_VISITS` | Візити та промо-активності: тривалість, зразки, нотатки | Одна активність |
| `PRESCRIPTIONS` | Призначення лікарів із CRM: пацієнти, кількість призначень | Один запис |
| `ADVERSE_EVENTS` | Фармаконагляд: серйозність, наслідок, джерело повідомлення | Версія кейсу |

**Чому джерелу не можна вірити напряму:** повні дублікати рядків у фактах, посилання на
неіснуючих клієнтів і склади, дати поза робочим періодом, суми, що не сходяться з кількістю ×
ціною, типи рухів то українською, то англійською.

## 2. Silver (`whsilver.dwh`) — очищена модель

### Факти

| Обʼєкт | Що показує | Зернистість | Основні міри |
|---|---|---|---|
| `FctSales` | Продажі клієнтам | рядок замовлення | `Qty`, `GrossAmount`, `DiscountAmount`, `NetAmount`, `IsReturn`, `IsCancelled` |
| `FctInventoryMovement` | Рух товару по складах | складський рух | `Qty`, `QtySigned` (прихід +, видача й списання −) |
| `FctVisit` | Робота польової команди | активність | `VisitCnt`, `DurationMin`, `SamplesQty` |
| `FctPrescription` | Призначення лікарів | запис призначення | `PatientsCnt`, `PrescriptionsCnt` |
| `FctAdverseEvent` | Побічні явища | версія кейсу | `CaseCnt`, `IsLatestVersion`, `IsLogicalError` |

### Виміри

| Обʼєкт | Що містить |
|---|---|
| `DimProduct` | Препарат: назва, SKU, МНН, АТС-код і клас, форма, дозування, виробник, RX/OTC, ціна |
| `DimClientAccount` | Клієнт після склеювання дублів; `SrcDuplicateCnt` — скільки кодів джерела злилися |
| `DimDoctor` | Лікар після склеювання дублів: ПІБ, спеціальність, ЛПУ, регіон, сегмент |
| `DimEmployee` | Співробітник: роль, територія, лінія RX/OTC, керівник, дата найму |
| `DimWarehouse` | Склад: тип, власник (консигнація), регіон, місто |
| `DimManufacturer`, `DimAtcClass` | Виробник і анатомічна група АТС |
| `DimRegion`, `DimCity`, `DimTerritory` | Географія й торгова територія |
| `DimChain`, `DimLegalEntity` | Аптечна мережа та юрособа (ЄДРПОУ) — база склеювання клієнтів |
| `DimSpecialty`, `DimLpu` | Спеціальність лікаря та медзаклад |
| `DimActivityType` | Візит / круглий стіл / e-detailing / симпозіум + ознаки дистанційної та групової |
| `DimAeSeriousness`, `DimAeOutcome`, `DimReportSource` | Класифікатори фармаконагляду |
| `DimDate` | Календар: день, місяць, квартал, рік, фінансовий рік і квартал |
| `DimCurrency`, `DimOrderStatus`, `DimMovementType`, `DimSrcSystem` | Керовані словники |

### Довідники відповідності (`Ref*`)

Службові обʼєкти: памʼятають, який код джерела відповідає якому «золотому» запису. Завдяки їм
продаж, заведений на код-дубль аптеки, потрапляє на правильного клієнта. Для звітності напряму
не потрібні.

| Обʼєкт | Що зіставляє |
|---|---|
| `RefClientAccount` | Код клієнта в ERP → золотий клієнт; `IsGoldenRecord` — чи це основний код |
| `RefDoctor` | Код лікаря → золотий лікар |
| `RefProduct`, `RefEmployee`, `RefWarehouse` | Коди препарату, співробітника, складу → виміри |
| `RefMovementType` | Сирий тип руху («Прихід», «IN», «Списання») → канонічний тип зі знаком |

## 3. Gold (`whgold.dwh`) — вітрина звітності

Без технічних ключів і версій: поточний стан довідників і згорнуті цифри. Склад — див.
[`gold_model.md`](gold_model.md).

| Агрегат | Яке питання закриває |
|---|---|
| `AggSalesDaily` | Щоденна динаміка продажів, звірка з відвантаженнями |
| `AggSalesMonthly` | Місячні продажі, повернення окремо, охоплення клієнтів |
| `AggVisitMonthly` | Активність польової команди й охоплення лікарів |
| `AggPrescriptionMonthly` | Динаміка призначень, скільки лікарів призначають препарат |
| `AggInventoryMonthly` | Прихід, видача, списання, чистий рух запасів |
| `AggAdverseEventMonthly` | Кейси фармаконагляду, з них летальні |
| `AggPromoEffectMonthly` | Промо проти результату: візити, зразки, призначення, продажі, сума на візит |

## 4. Як читати ключі

| Поняття | Пояснення |
|---|---|
| `SK…ID` / `SK…KeyID` | Перший — код версії рядка, другий — стабільний код обʼєкта. Факти посилаються на другий, тож препарат не «розпадається» після зміни ціни |
| `StartDate` / `EndDate` | Період дії версії; поточна — де `EndDate` порожній. Так видно, яким був сегмент лікаря торік |
| Рядок `-1` | «Невідомо». Продаж із посиланням на відсутнього клієнта потрапляє сюди, а не зникає зі звіту |
| `IsDeleted` | Запис зник із джерела; з історії його не видаляють, щоб старі періоди лишались відтворюваними |

## 5. Прапорці якості

Silver нічого не викидає — сумнівні рядки лишаються, але позначені. Фільтрувати їх чи ні —
рішення бізнесу.

| Прапорець | Що означає | Де |
|---|---|---|
| `IsSrcDuplicate` | У джерелі було кілька однакових рядків; у факт потрапив один | усі факти |
| `IsAmountConsistent` | Сума рядка сходиться з кількістю × ціною × знижкою | `FctSales` |
| `IsPeriodOutOfRange` | Дата замовлення поза робочим періодом | `FctSales` |
| `IsQtyOutlier` | Аномальна кількість руху (> 100 000) | `FctInventoryMovement` |
| `IsLogicalError` | Критична серйозність із наслідком «одужав» | `FctAdverseEvent` |
| `IsAtcCodeValid` | АТС-код не відповідає жодній анатомічній групі | `DimProduct` |

## 6. Свіжість даних

Факти оновлюються інкрементально (щодня нові та змінені рядки), раз на тиждень — повне
перезавантаження, яке підхоплює й видалення в джерелі. Виміри звіряються повністю щоразу,
тому зміна атрибута видно вже наступного дня.
