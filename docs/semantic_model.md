# Семантична модель `PharmaSalesGold`

Модель над gold-шаром (`whgold.dwh`) для Copilot і ad-hoc звітності. Зберігається як TMDL —
той самий формат, у якому Fabric тримає семантичні моделі в git integration, тож деплоїться
разом із репозиторієм, а не збирається руками в UI.

```
fabric-semantic-model/PharmaSalesGold.SemanticModel/
├── .platform                      -- метадані Fabric-айтема
├── definition.pbism
└── definition/
    ├── database.tmdl
    ├── model.tmdl                 -- культура uk-UA, перелік таблиць
    ├── expressions.tmdl           -- підключення до whgold (Direct Lake)
    ├── relationships.tmdl         -- 20 звʼязків
    ├── cultures/uk-UA.tmdl        -- синоніми для Copilot / Q&A
    └── tables/*.tmdl              -- 13 таблиць
```

## 1. Чекліст із `copilot_prompts.md` — як реалізовано

| Пункт | Реалізація |
|---|---|
| 1. Звʼязки агрегатів із вимірами | 20 звʼязків у `relationships.tmdl`, усі «багато до одного», однонаправлені (TMDL-типове) |
| 2. Сховати технічні колонки | усі `SK…ID`, `Id`, `CreatedBy`, `CreatedAt` мають `isHidden`; числові колонки під мірами теж приховані |
| 3. Календар як таблиця дат | `dataCategory: Time` + `isKey` на колонці `Дата`; **усі 7 агрегатів** звʼязані з календарем |
| 4. Міри бізнес-мовою | 35 мір: «Сума продажів», «Кількість упаковок», «Візити», «Списано», «Кейси»… |
| 5. Синоніми | `cultures/uk-UA.tmdl`: «виручка», «оборот», «медпред», «ЛПУ», «рецепти» + англомовні (`sales`, `revenue`, `visits`, `prescriptions`) |
| 6. Описи | `///`-коментарі на таблицях, колонках і мірах — Copilot читає їх при доборі полів |
| 7. Заборона підсумовування відношень | відношення реалізовані як `DIVIDE(...)`-міри, а не колонки: «Сума продажів на візит», «Частка повернень», «Середня знижка, %», «Призначень на пацієнта» — вони перераховуються на кожному рівні |

Додатково: `discourageImplicitMeasures` у моделі — користувач не зможе випадково перетягнути
приховану колонку й отримати неявну суму.

## 2. Що знадобилося змінити в gold

Місячні агрегати не мали жодної колонки з датою — тільки `YearMonth`/`YearNum`/`MonthNum`.
Звʼязати їх із календарем було нічим, а без цього не працюють ані квартали, ані порівняння
з минулим роком (пункт 3 чекліста) для шести агрегатів із семи.

**`V260828.1000__gold_add_month_date_key.sql`** додає `MonthStartDate` (перший день місяця)
у шість місячних агрегатів і в їхні `v*`. Після деплою потрібен один повний прогін gold:

```sql
EXEC [dwh].[spGoldFullLoad] @load_id = 'after_month_date_key';
```

Власні часові колонки агрегатів (`YearMonth`, `YearNum`, `MonthNum`) у моделі приховані —
увесь час береться з `Календар`, щоб Copilot не мав двох джерел періоду.

## 3. Іменування

| Таблиця gold | У моделі |
|---|---|
| `DimDate` | Календар |
| `DimProduct` | Препарат |
| `DimClientAccount` | Клієнт |
| `DimDoctor` | Лікар |
| `DimEmployee` | Представник |
| `DimWarehouse` | Склад |
| `AggSalesMonthly` | Продажі за місяць |
| `AggSalesDaily` | Продажі за день |
| `AggVisitMonthly` | Візити |
| `AggPrescriptionMonthly` | Призначення |
| `AggInventoryMonthly` | Рухи запасів |
| `AggAdverseEventMonthly` | Побічні явища |
| `AggPromoEffectMonthly` | Промо проти продажів |

Міри двох таблиць продажів названі по-різному («Сума продажів» проти «Сума продажів за день»),
щоб Copilot не плутав місячний і денний зрізи — вони по-різному трактують повернення.

## 4. Міри, що потребують уваги

| Міра | Чому нестандартна |
|---|---|
| `Клієнтів, що купували` | `DISTINCTCOUNT` по денному агрегату — коректна на будь-якому рівні (день, місяць, рік) |
| `Лікарів охоплено (місяць)` | `IF(HASONEVALUE(…))`: за кількох місяців одразу повертає порожньо замість завищеної суми |
| `Лікарів, що призначали (місяць)` | те саме |
| `Сума продажів на візит` | `DIVIDE` двох мір — перераховується, а не підсумовується |
| `Частка повернень` | `DIVIDE`; знаменник — валовий оборот (продажі + повернення) |

## 5. Деплой

1. Підставити в `definition/expressions.tmdl` SQL endpoint і item id warehouse `whgold`
   замість `<SQL_ENDPOINT>` і `<WHGOLD_ITEM_ID>`.
2. Синхронізувати репозиторій через **Fabric → Workspace → Git integration**
   (`logicalId` у `.platform` заповнений нулями — Fabric призначить свій при першій синхронізації).
3. Альтернатива без git: відкрити папку `.SemanticModel` у Power BI Desktop (TMDL view)
   або застосувати через Tabular Editor / `fabric-cli`.
4. Після публікації перевірити в Copilot три питання з різних доменів — і, за потреби,
   дописати синоніми в `cultures/uk-UA.tmdl`.

## 6. Що навмисно не зроблено

* **RLS не налаштований** — для прототипа всі бачать усі регіони. Якщо потрібно
  обмежити представників своєю територією, це окремий крок (ролі + фільтр по `DimEmployee`).
* **Перспективи (perspectives) не створені** — модель невелика, 13 таблиць видно цілком.
* **Календар не має позначок майбутніх періодів** — у `DimDate` є дати на 10 років уперед,
  тож у візуалах без фільтра періоду буде довгий «хвіст» порожніх місяців. Для дашбордів
  варто одразу ставити фільтр по періоду.
